# Adaptive Learning Platform

A computational learning system where **custom ML owns student modeling,
prediction, and adaptation**, and LLMs are one component (content generation),
never the decision-maker. The ML engine decides WHAT and WHY; the LLM decides HOW.

Design research: `../docs/phase1-research-and-formulation.md` ·
Machine-readable status: `STATUS.json` · Experiment records: `experiments/registry.jsonl`

## Quickstart

```bash
pip install fastapi uvicorn sqlalchemy pydantic numpy scikit-learn pandas pypdf python-docx python-pptx httpx
# research extras: torch (cpu wheel) pyarrow
cd adaptive-platform
uvicorn alpa.api.app:app --reload     # UI + API at http://localhost:8000
pytest                                  # 66 tests
python scripts/run_kt_eval.py --stage shallow    # KT benchmark (see below)
python scripts/demo_llm_session.py      # live PDF->graph->session demo (mock LLM endpoint)
```

Open `http://localhost:8000` — the web client lets a student paste or upload
any material (notes, a chapter, a slide deck, or just a topic list); it's
ingested into the concept graph, auto-approved for immediate study (prototype
mode — no human-review queue yet), and the adaptive loop starts picking items
from it right away.

### Free real LLM content (optional)

By default all content generation runs on the deterministic, offline
`TemplateProvider` — no key, no signup, no cost, but pedagogically minimal.
To get real explanations/examples/questions, copy `.env.example` to `.env`,
uncomment ONE option (Groq free tier, Google AI Studio free tier, OpenRouter
free models, or a fully local Ollama model), then:

```bash
set -a; source .env; set +a
uvicorn alpa.api.app:app --reload
```

`GET /api/health` reports `"llm_coupled": true` and which provider is active
once configured. The engine's decisions (what to teach, what to test) are
never generated by the LLM — see "Architecture" — only the wording is.

## Architecture

```
core/        model math, policy, diagnostic, state, graph   (pure, DB-free, unit-tested)
db/          versioned schema: graph, states, attempts, interventions,
             model_predictions (append-only), model/policy versions, experiments
engine.py    orchestration: diagnostic loop, adaptive loop, grading, logging,
             ingestion persistence, approval gate
content/     provider abstraction (LLM ABC + registry; deterministic
             TemplateProvider; HTTPChatProvider for any OpenAI-compatible
             chat-completions endpoint), ingestion (PDF/PPTX/DOCX/TXT/topics ->
             provenance-stamped concept/edge proposals), question schema +
             validation + deterministic grading (MCQ / numerical / short answer)
research/    KT model zoo, leakage probes, evaluation protocol, synthetic
             simulator, policy evaluation, experiment registry
api/         FastAPI surface
web/         zero-dependency study client
```

## The loop (Phase J, validated end-to-end)

`GET /sessions/{id}/next` → decision `{intervention, concept, item?, p_correct,
uncertainty, rationale, exploration, payload(content_spec + generated_content)}`
→ `POST /sessions/{id}/attempts` (server-side grading, telemetry contract:
latency, hints, paste detection, confidence) → state transition → mastery
hysteresis → prediction + intervention logged → next decision.

`GET /interventions/{id}/trace` reconstructs: policy record → model version →
input features → prediction → outcome. This log is the future bandit/OPE dataset.

## Model & policy (implemented)

- **Student model:** PFA/IRT hybrid, power-law forgetting `R=(1+Δt/9s)^-α`,
  online Bayesian (Elo-class) updates, uncertainty as posterior variance with
  process noise. Mastery is a decision: `P(θ̃>θ_m)≥0.85` (demote `<0.80`) —
  separate from uncertainty by construction.
- **State:** schema-versioned, JSON-serializable, deterministic transitions
  (`core/state.py`); DB is the system of record.
- **Graph:** typed provenance-aware edges (`core/graph.py`); the adaptive loop
  traverses human-reviewed structure only; LLM proposals stay inert until
  `POST /concepts/{id}/approve`.
- **Policy:** rule table over (P(correct), error pattern, retention, fatigue)
  + information-gain item selection (Fisher tie-break; uncertainty-resolution
  branch) + ε-exploration over safe actions, logged with `exploration=true`.
- **Cold start:** max-Fisher-information diagnostic, budget-capped at 8.

## Measured results (VALIDATED, not claims)

**Phase A — knowledge tracing** (ASSISTments 2009 variant; 3,620 students;
student-level split; all leakage probes pass; report in
`experiments/reports/phase-a-consolidated.md`):

| model | test AUC | ECE |
|---|---|---|
| logistic_rich | 0.722 | 0.018 |
| gru_kt | **0.748** | 0.030 |
| dakt_attention | 0.722 | 0.029 |
| pfa_logistic | 0.701 | 0.027 |
| bkt_em | 0.698 | 0.020 |
| hybrid_production (untuned) | 0.675 | 0.073 |
| irt_2pl (static, θ=0 for new students) | 0.542 | 0.232 |

The 0.90 target is **not reached and not honestly reachable** under strict
student-level, prefix-only evaluation; historic ≥0.90 claims relied on leaky
interaction-level splits. Finding with a queued fix: the production hybrid
trails logistic-rich by +0.047 AUC (significant) — untuned defaults, fixed
discrimination, inactive forgetting term on timestamp-less data.

**Policy evaluation on planted synthetic students** (algorithm check, **never
human evidence**; 4 policies × 7 profiles × 150 students): adaptive rules
success 0.750 vs fixed-policy 0.723 vs random 0.474; mastery parity with fixed.
Two defects were found and fixed by this harness: misconception over-firing on
noisy learners, and an identical-evidence remediation loop (both have
regression tests).

## Honesty contract

- Every experiment is registry-recorded (append-only), seeded, and
  dataset-hashed; checkpoints under `experiments/checkpoints/`.
- Leakage probes run as part of model evaluation, not as decoration.
- Synthetic results validate algorithms, never human learning.
- No wall-clock timestamps in the public dataset ⇒ retention findings there use
  step-lag proxies and are labeled as such.
- The causal question — does adaptation improve *human* learning — is reserved
  for the pre-registered RCT; nothing in this repo substitutes for it.

## Deferred (explicit)

Paid LLM endpoints — `HTTPChatProvider` is wire-validated against a mock
OpenAI-compatible server over real TCP; pointing it at a production endpoint
needs an API key and a content-QA budget · offline IRT difficulty refit · bandit
upgrade (gated on logged exploration volume) · multi-KC per-attempt updates ·
structured/rubric items (external grading stays out of the core model until
separately instrumented) · human RCT.
